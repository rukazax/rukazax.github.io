dsh_hub

Один ноутбук, один настольный ПК, один телефон — и на каждом свой DeepSeek Harness со своими сессиями. Проект сводит их в федерацию: один экземпляр становится хабом, остальные узлами, и всё это видно из одного окна.

Обсудить внедрение Открытый код на GitHub

Что это

Федерация экземпляров DeepSeek Harness, а не ещё одна панель управления.

Чужие сессии в одном окне

Хаб видит сессии всех узлов, отправляет промпт в нужную и не подменяет устройство, на котором она живёт.

Ключи моделей — в одном месте

Права и LLM-ключи живут на хабе. Узлам свои не нужны: пропал ключ — запрос падает, а не уходит «куда-нибудь».

Одна общая память

Узлы присылают чанки работы, хаб собирает из них единый поисковый слой с пометкой workspace и узла.

Офлайн не ломает картину

Узел живёт своей жизнью: своя работа, свои сессии. Выключили — он догонит, когда вернётся.

Телефон в двух ролях

Пульт для управления федерацией и, при разрешении, исполнитель на своём устройстве.

Ядро не трогаем

Всё живёт плагинами профиля и файлами состояния, поэтому обновление DSH не превращается в починку федерации.

Как устроено

Хаб, узлы, телефон и один протокол между ними.

Хаб

HTTP и SSE на локальном порту, SQLite без зависимостей, снапшоты сессий, очередь команд и аудит.

Узел

Плагин в профиле DSH: спаривание по коду, отправка индекса, приём команд и исполнение у себя.

Телефон

Нативное приложение на Kotlin и Compose: узлы, сессии, переписка, промпты, подтверждения.

Протокол

proto 1, идемпотентные commandId, курсоры Last-Event-ID на обоих потоках событий.

Что уже работает

Хаб v0: спаривание, обмен и хранение проверены тестами, а не обещаниями.

Спаривание узлов

Узел приходит по коду, получает токен и начинает отправлять индекс. Чужой код отбивается.

Устойчивость данных

Списки узлов и сессий переживают перезапуск хаба; повторный индекс не плодит дубли.

Закрытые списки

Без токена хаба списки недоступны — проверка входит в тестовый набор.

Дальше по плану

Память, исполнение промптов с подтверждениями, права видимости, статистика расходов.

Приватность по умолчанию

Здесь она не лозунг, а следствие архитектуры.

Исполнение — только у хозяина

Сессия живёт на своём устройстве. Хаб управляет, но не исполняет чужие ходы за спиной владельца.

Опасное — по подтверждению

Инструменты уровня оболочки спрашивают разрешение, каждое решение пишется в аудит, «стоп» гасит команды.

Исходящие соединения

Узел сам стучится на хаб по HTTPS с токеном: входящих портов на узлах не требуется.

Без телеметрии

Никаких внешних сервисов: данные ходят между вашими устройствами.

Статус проекта

dsh_hub в разработке: хаб v0 готов, дальше — память, исполнение промптов, права видимости и Android-приложение. Репозиторий открыт под MIT, план и протокол лежат рядом с кодом.
